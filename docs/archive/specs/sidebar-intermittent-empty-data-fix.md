# Sidebar 小工具有時候沒有資料進來

- **作者**：Claude（診斷會話）
- **日期**：2026-09-20
- **狀態**：Draft
- **對應使用者回報**：「11. SIDEBAR有時候沒有資料進來」

## 1. 已知背景（先讀，避免重複調查已修好的問題）

- 全站曾有一個「地理定位權限彈窗競賽」的 bug：`getCurrentPosition` 用固定 6~10 秒逾時，沒有考慮瀏覽器自己的「是否允許定位」彈窗還沒被使用者點掉的情況，導致回應慢的使用者被靜默預設成某個固定地點（例如台北101）。這個 bug 已在 4 個獨立呼叫點修好，PR #174（`fix/geolocation-permission-timeout`）已於 2026-09-09 合併進 `main`。**請先確認這個修復是否已經涵蓋所有 sidebar widget 用到的地理定位路徑**（不要假設全部涵蓋到，因為當初是分頭修 4 個呼叫點，可能還有漏網之魚），若發現還有 sidebar widget 使用未修好的舊版逾時邏輯，直接套用同樣的修法；若確認都已涵蓋，則這不是本次的根因，往下一項調查。
- 使用者沒有指名是哪一個 sidebar widget，全站目前至少有以下幾個獨立的 sidebar widget，都可能是使用者說的「SIDEBAR」：`AqiSidebarWidget`、`UvSidebarWidget`、`CdcAlertSidebarWidget`、`CpcPriceSidebarWidget`、`EarthquakeSidebarWidget`、`ErStatusSidebarWidget`、`PestAlertSidebarWidget`、`WaterOutageSidebarWidget`、`WeatherAlertSidebarWidget`，共用的殼元件是 `SidebarWidgetShell.tsx`（目前只有 Aqi/Uv 兩個真正共用它，其餘各自獨立排版）。

## 2. 待辦事項

1. 逐一檢查上述每個 sidebar widget 的資料抓取邏輯，找出「有時候會顯示空狀態（例如『暫無測站資料』）但其實資料應該存在」的情況，區分兩種根本原因類型：
   - **地理定位相關**：依賴使用者座標的 widget（Aqi、Uv 等），若座標尚未解析完成就先發送請求、或座標解析失敗時沒有適當的重試/等待邏輯，可能查不到最近測站。
   - **與地理定位無關**：純粹是 API 請求失敗、逾時、後端查詢在特定條件下回傳空陣列（例如某些縣市/座標範圍剛好沒有涵蓋的測站、資料庫連線瞬斷等）。
2. 用實際測試重現：至少挑 2~3 個 widget，模擬「網路稍慢」「地理定位彈窗慢按」「切換頁面/元件重新掛載」等情境，確認是否真的會出現空狀態，記錄具體重現步驟。
3. 針對確認重現的 bug 直接修正（例如補上載入中狀態與座標就緒後才發送請求的防呆、失敗時的重試邏輯、後端查詢半徑不足時擴大搜尋半徑等），不需要每個 widget 都動，只修真的有問題的部分，避免不必要的大範圍重構。
4. 若排查後發現全部 widget 目前實際上都運作正常、無法重現空資料情況，如實記錄在 PR 說明中（包含測試過程），不要為了「有交付」而硬改沒問題的程式碼。

## 3. 驗收標準

- 針對每一個被確認有問題的 widget，說明根因、修法，並附上修復前後的重現/驗證方式。
- `npm test` 通過。
- PR 說明需列出「已檢查但確認沒問題」與「有問題且已修復」的 widget 清單，讓人工可以快速複核涵蓋範圍。
