- **日期**：2026-09-20
- **狀態**：Findings delivered（見 `docs/specs/news-image-pipeline-findings.md`）
- **對應使用者回報**：「4. 新聞卡片大部分都還是沒有抓到正確圖片」

## 1. 任務性質

**這是一份診斷報告任務，不是修 bug 任務。** 完成後的交付物是一份 Markdown 報告（存成 `docs/specs/news-image-pipeline-findings.md`），內容包含流程說明、抓不到圖片的具體原因分類、與優化建議。**不要動任何 production 程式邏輯**，只有這份報告本身需要被建立並提交（開 PR）。

已知背景（避免重複調查）：本站過去修過一次 `public/images/news/articles` 目錄權限（EACCES）導致 OG 圖片全部抓取失敗的事故，該次已修復並清空積壓。但使用者現在回報「大部分還是沒抓到正確圖片」，代表可能是**不同的**新問題，或是同一根因的其他變形，需要重新從頭盤點，不要假設是同一個 bug。

## 2. 待辦事項

1. **列出目前抓圖流程**：從新聞來源進站（RSS/爬蟲）開始，到圖片最終顯示在新聞卡片上，經過哪些檔案/函式（預期會經過 `lib/server/images/fetchOpenGraphImage.ts`、`scripts/gha-og-external-backfill.mjs`、`.github/workflows/news-og-backfill.yml`、`lib/server/news/cleanupChromeAssets.ts` 等，實際請以程式碼為準，不要照抄本清單）。畫出或條列出完整的資料流。
2. **抽樣調查目前實際「抓不到正確圖片」的新聞**：直接查資料庫或呼叫既有 API，抽樣近期一批新聞，統計有多少比例沒有圖片／圖片是預設圖／圖片連結失效，並針對抓不到的案例，分類根本原因（例如：來源網站本身沒有 og:image、被反爬蟲擋掉、圖片格式不支援、抓圖逾時、圖床網域被牆、圖片抓到了但顯示失敗等），每一類至少舉 2~3 個實際案例（新聞標題/ID/來源網域）佐證，不要憑印象猜測。
3. **上網查詢**目前業界對於 RSS/新聞聚合站「大量新聞來源抓取代表性圖片」常見的優化作法（例如：oEmbed、srcset 挑圖策略、fallback 圖片策略、快取與重試策略、對特定常見來源網域建立客製化抓圖規則等），列出 2~3 個具體可行、適合本站規模的建議，並簡述優缺點。
4. **降低主機負擔角度**：目前抓圖排程（`news-og-backfill.yml` 一小時兩次）本身對主機的負擔是多少（呼叫次數、耗時、是否會佔用 SSH connection），有沒有辦法在不犧牲抓圖成功率的前提下降低頻率或改成更省資源的做法（例如只在新文章進站時觸發、而不是全量重跑）。
