## 1. 任務性質

**這是一份診斷報告任務，不是重構任務。** 交付物是一份 Markdown 報告（`docs/specs/map-technology-findings.md`）。**不要在本工單內統一重寫或修改任何地圖元件**，只需盤點現況並提出建議，供人工複核後再決定是否值得重寫。

已知背景（避免重複調查起點，但仍需自行完整盤點，不要只看這幾個）：初步搜尋已發現至少 `components/News/NewsMapCard.tsx`（OpenStreetMap embed iframe）、`components/Tools/LocalWeatherSvgWidget.tsx`（自製 SVG 地圖）、以及疑似使用 Google Maps 連結（`googleMapsUrl`）的多處元件並存。注意：`NewsMapCard` 已在另一張工單（[[remove-news-article-geolocation-card]]）中被要求整個移除，若該工單已先合併，盤點時請以移除後的現況為準，不要把它算進「需要統一」的清單裡。

## 2. 待辦事項

1. 全站搜尋所有跟地圖顯示相關的元件與技術（Leaflet、Google Maps iframe/連結、OpenStreetMap embed、自製 SVG/Canvas 地圖等），列出：
   - 使用的技術/函式庫
   - 出現在哪些頁面/元件
   - 是否需要外部 API key、是否有已知的用量限制或費用
   - 互動能力差異（可縮放/可點擊標記/僅靜態圖片）
2. 評估統一的可行性與代價：如果要統一成單一技術方案，
   - 哪個方案最適合本站規模（流量、預算、目前已知的主機負擔限制）？
   - 統一後預估要改動哪些檔案／頁面數量？
   - 有沒有哪些現有用法因為特殊需求（例如需要離線/無 API key/客製化視覺）不適合被統一，需要保留例外？
3. 上網查詢目前業界（尤其是中小型內容網站）在地圖技術選型上的常見考量與建議方案。

## 3. 交付物

- `docs/specs/map-technology-findings.md`：包含現況盤點表格、統一可行性評估、具體建議方案（含理由與代價評估）。
- 不需要（也不應該）在本工單內修改任何地圖元件程式碼。
