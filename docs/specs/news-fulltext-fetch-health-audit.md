# 新聞全文抓取健康度審查（僅產出報告，不要改程式碼）

- **作者**：Claude（診斷會話）
- **日期**：2026-09-20
- **狀態**：Draft
- **對應使用者回報**：「3. 自由時報－生活與健康新聞的連結點進都會出現403」「10. 官方機構的新聞是否都有爬全文進來」

## 1. 任務性質

**這是一份診斷報告任務，不是修 bug 任務。** 交付物是一份 Markdown 報告（`docs/specs/news-fulltext-fetch-findings.md`），盤點全站所有新聞來源的全文抓取健康度。**不要動任何 production 程式邏輯**，只需建立報告並提交（開 PR）。

這兩項使用者回報本質上是同一件事的兩個症狀：全文抓取管道是否正常運作。自由時報的 403 是其中一個具體案例，第10項是問「還有沒有其他來源也有類似問題」，因此合併成一次全面盤點。

## 2. 待辦事項

1. **確認自由時報 403 的真正發生位置**：先搞清楚是（a）使用者點擊新聞卡連到站內文章頁時，站內伺服器端抓取自由時報原文失敗回傳 403、還是（b）新聞卡的連結是直接連到自由時報原站網址（`target="_blank"`），使用者瀏覽器直接打開自由時報網站時被自由時報自己的防盜連/反爬蟲機制擋下（例如檢查 Referer）。這兩者的修法完全不同，務必先用實際測試（用 curl 模擬伺服器端抓取 vs. 用瀏覽器模擬直接開啟連結，比對 headers/Referer 差異）確認，不要用猜的。
2. **盤點所有新聞來源的全文抓取狀態**：參考 `lib/server/config/rss-feeds.ts`、`lib/server/rss/fetchDetailPage.ts`、`lib/server/rss/runIngestion.ts` 找出全部啟用中的新聞來源，抽樣檢查每個來源的近期文章，統計並分類：
   - 完全抓到全文的來源
   - 只抓到摘要／RSS 原文片段、沒有全文的來源（原因為何：來源本身 RSS 沒提供全文？還是有嘗試抓詳情頁但失敗？）
   - 會回傳 403 / 405 / 429 等明確被擋的來源（列出 HTTP 狀態碼與來源網域）
   - 官方機構（衛福部、疾管署等政府單位）來源是否都有成功抓到全文，若沒有，逐一列出原因
3. **上網查詢**業界對於「聚合多個新聞來源、部分來源有反爬蟲/防盜連機制」的常見合規優化做法（例如尊重 robots.txt 的前提下如何合法取得可用摘要、對外連結時保留適當 Referrer 政策、對特定來源改用官方 RSS 全文欄位而非另外爬詳情頁等），列出可行建議。
4. 每一類發現至少舉 2~3 個實際案例（新聞標題/來源網域/HTTP 狀態碼）佐證。

## 3. 交付物

- `docs/specs/news-fulltext-fetch-findings.md`：包含 403 根因判定結果、全來源盤點表格、優化建議。
- 不需要（也不應該）在本工單內修改任何抓取相關程式碼。
